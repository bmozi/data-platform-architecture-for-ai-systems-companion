# Pilot and Usability Route

Use this route to test whether a cross-functional group can make a bounded
AI-data readiness decision without the author or facilitator supplying the
missing judgment.

## Status ladder

Use only the highest supported label: **Prepared**, **Piloted**, **Revised**,
**Repeated**, or **Practitioner-tested**. This reader-value layer is currently
**Prepared**. Existing Cedar Vale materials and blank logs do not establish a
completed test result.

## First pilot

1. Review the protocol boundary in [testing/README.md](testing/README.md).
2. Use the separately versioned
   [AI-Ready Data Reader-Value Pilot Packet](testing/ai-ready-data-reader-value-v1/README.md)
   when testing the new journey and cross-role decision layer.
3. During that scored packet, supply only its declared participant materials;
   its live update provides the failure challenge. Use the standalone
   [Failure Lab](FAILURE-LAB.md) for workshops or separate exercises, not as an
   extra packet handout.
4. Include at least one domain or business participant and one person outside
   the data/AI implementation team.
5. Observe whether they can name the use, resolve or escalate meaning, identify
   a prohibited inference, define abstention, and preserve separate action and
   release gates.
6. Record time to first useful artifact, confusion, disagreements, omitted
   consequences, and unsupported confidence.
7. Use [the usability log](companion-usability-log.md) only for sessions that
   actually occur.

## No-result rule

Repository validation, a constructed example, an author walkthrough, or an
unrun protocol is not usability evidence. Preserve negative and boundary
findings with successes.
